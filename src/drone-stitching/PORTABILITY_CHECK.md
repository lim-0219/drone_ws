# 배포 폴더 재현 확인

검증일: 2026-10-13 (Asia/Seoul).

원래 개발 폴더와 다른, 공백이 포함된 경로에 배포 대상 파일만 복사했습니다. 그 안에 새 가상 환경을 만들고 고정 의존성과 프로젝트를 새로 설치한 뒤 아래를 확인했습니다. 기존 개발 가상 환경의 패키지를 공유하지 않았고, 설치된 프로젝트가 복사한 소스를 읽는지도 확인했습니다.

## 확인한 환경과 결과

- 환경: macOS 15.6.1 ARM64, Python 3.12.14, CPU 실행.
- 라이브러리: opencv-python-headless 4.10.0.84, NumPy 1.26.4, SciPy 1.14.1, pytest 8.3.5.
- 새 환경의 의존성 검사: `No broken requirements found`.
- 자동 테스트: **27 passed in 21.55s**.
- 설치 후 합성 실행 도우미: SIFT+메타데이터와 ORB+격자 모두 성공, 각각 이웃 연결 20/20.
- 합성 지도 크기: SIFT 1062×2009 px, ORB 1060×2008 px.
- 합성 좌표 RMSE: SIFT 약 0.000307m, ORB 약 0.004684m. 생성 정답에 대한 값이며 실비행 정확도가 아닙니다.
- 설치 후 Sheffield 실행 도우미: **20/20 연결 통과, 2315×2617 px 지도 생성**.
- Sheffield 원점 변환: 로컬 (0,0)m → 지도 (1147,1300)px, 유효 촬영 영역 내부.
- 동봉된 기존 결과 3종의 원점·유효 영역 변환 정상.
- 동봉 결과의 이미지 상대 경로 27개가 실제 파일로 연결되고 원본 SHA-256과 일치.

프로젝트의 핵심 정합 코드는 변경하지 않았습니다. 배포용 결과에서는 사진 파일 경로만 `transforms.json` 폴더 기준 상대 경로로 바꾸고 경로 기준을 기록했습니다. 원본 사진 바이트, 변환 행렬, 정합 수치와 기존 실행 환경 기록은 보존했습니다.

검증은 같은 macOS 컴퓨터에서 새 경로·새 Python 환경으로 수행했습니다. **Ubuntu 22.04/Windows 및 실제 다른 하드웨어에서 실행한 결과는 아닙니다.** Ubuntu용 설치 절차와 Python 3.10~3.12용 의존성을 제공하며, 해당 PC의 실행 결과는 그 PC에서 데모와 자동 테스트로 확인해야 합니다. GPU 성능이나 실측 지상 거리 정확도 역시 이 확인에 포함하지 않습니다.

새로 실행한 검증 결과는 중복 용량을 줄이기 위해 압축에 다시 넣지 않았습니다. 압축에는 앞서 기록한 기준 결과를 포함하며, `scripts/run_demo.py`로 새로운 실행 결과를 만들 수 있습니다.

## 압축을 옮긴 뒤 확인

```bash
python3 scripts/verify_bundle.py
```

`BUNDLE_MANIFEST.json`에 기록한 모든 배포 파일의 SHA-256을 확인합니다. 이후 소스나 설정을 수정하면 해당 파일의 해시는 달라집니다. 설치로 추가되는 가상 환경이나 새로운 실행 결과는 검사 대상에 포함하지 않습니다.
